# 要件ドキュメント

## 概要

複数人での使用を想定した割り勘+家計簿アプリケーション。ユーザーがグループを作成し、支払いを記録・管理し、精算状況を追跡できるWebアプリケーションです。

## 要件

### 要件1：ユーザー認証

**ユーザーストーリー:** ユーザーとして、アプリにログインして自分のアカウントにアクセスしたい。そうすることで、個人の支払い記録やグループ情報を安全に管理できる。

#### 受け入れ基準

1. WHEN ユーザーがログインページにアクセス THEN システムはユーザー名とパスワードの入力フィールドを表示する
2. WHEN ユーザーが有効な認証情報を入力 THEN システムはユーザーをトップページにリダイレクトする
3. WHEN ユーザーが無効な認証情報を入力 THEN システムはエラーメッセージを表示する
4. WHEN ユーザーがログイン状態 THEN システムはマイページでユーザープロフィールを表示する

### 要件2：ユーザーグループ管理

**ユーザーストーリー:** ユーザーとして、支払いを共有するグループを作成・管理したい。そうすることで、家族や友人と一緒に家計を管理できる。

#### 受け入れ基準

1. WHEN ユーザーがグループ作成ページにアクセス THEN システムはグループ名入力とメンバー招待フィールドを表示する
2. WHEN ユーザーが必要事項を入力してグループを作成 THEN システムは新しいグループを作成し、グループ詳細ページにリダイレクトする
3. WHEN ユーザーがグループ一覧ページにアクセス THEN システムは参加しているグループの一覧を表示する
4. WHEN ユーザーがグループ詳細ページにアクセス THEN システムはグループ情報とメンバー一覧を表示する

### 要件3：支払い記録管理

**ユーザーストーリー:** ユーザーとして、グループ内での支払いを詳細に記録したい。そうすることで、誰がいくら支払うべきか、実際に誰が支払ったかを正確に追跡できる。

#### 受け入れ基準

1. WHEN ユーザーが支払い登録ページにアクセス THEN システムは日付選択、タイトル、収支区分、カテゴリ、支払い配分の入力フィールドを表示する
2. WHEN ユーザーが支払い情報を入力して登録 THEN システムは支払い記録を保存し、支払い詳細ページにリダイレクトする
3. WHEN ユーザーが「続けて入力する」ボタンを押下 THEN システムは同じ設定で新しい支払い登録フォームを表示する
4. WHEN ユーザーが支払い詳細ページにアクセス THEN システムは支払い記録と精算状況を表示する
5. IF 支払いが未精算 THEN システムは誰が誰にいくら支払うべきかを表示する

### 要件4：精算管理

**ユーザーストーリー:** ユーザーとして、支払いの精算状況を管理したい。そうすることで、グループ内での金銭のやり取りを明確にできる。

#### 受け入れ基準

1. WHEN ユーザーが支払い詳細ページで「精算済みにする」ボタンを押下 THEN システムはその支払いを精算済み状態に更新する
2. WHEN ユーザーが期間別支払い一覧ページにアクセス THEN システムは未精算分の支払い一覧と精算すべき金額を表示する
3. WHEN ユーザーが「全て精算済みにする」ボタンを押下 THEN システムは確認ポップアップを表示する
4. WHEN ユーザーが確認ポップアップで承認 THEN システムは該当期間の全ての未精算支払いを精算済みに更新する

### 要件5：支払い履歴閲覧

**ユーザーストーリー:** ユーザーとして、様々な期間での支払い履歴を閲覧したい。そうすることで、支出パターンを把握し、精算状況を確認できる。

#### 受け入れ基準

1. WHEN ユーザーが支払い一覧ページにアクセス THEN システムはデフォルトで未精算のみの支払い一覧を表示する
2. WHEN ユーザーが表示設定を変更 THEN システムは精算済みを含む支払い一覧を表示する
3. WHEN ユーザーが日毎/月毎/年毎の期間を選択 THEN システムは該当期間の支払い記録を表示する
4. WHEN ユーザーが特定の支払い記録を選択 THEN システムは支払い詳細ページを表示する

### 要件6：ダッシュボード機能

**ユーザーストーリー:** ユーザーとして、グループの収支状況を視覚的に把握したい。そうすることで、家計の全体像を理解し、将来の計画を立てられる。

#### 受け入れ基準

1. WHEN ユーザーがダッシュボードページにアクセス THEN システムはグループ全体の収入額・支出額を表示する
2. WHEN ダッシュボードが表示される THEN システムはユーザーごとの収支情報を表示する
3. WHEN ダッシュボードが表示される THEN システムはカテゴリごとの収支額と割合をグラフで表示する
4. WHEN ダッシュボードが表示される THEN システムは今後の予測情報を表示する

### 要件7：カテゴリ管理

**ユーザーストーリー:** ユーザーとして、支払いのカテゴリを管理したい。そうすることで、支出を分類し、分析しやすくできる。

#### 受け入れ基準

1. WHEN ユーザーがカテゴリ一覧ページにアクセス THEN システムはグループのカテゴリ一覧を表示する
2. WHEN ユーザーがカテゴリ作成ページにアクセス THEN システムはカテゴリ名入力フィールドを表示する
3. WHEN ユーザーがカテゴリを作成 THEN システムは新しいカテゴリを保存し、カテゴリ一覧ページにリダイレクトする
4. WHEN ユーザーがカテゴリ詳細ページにアクセス THEN システムはカテゴリ情報と編集・削除オプションを表示する

### 要件8：レスポンシブUI

**ユーザーストーリー:** ユーザーとして、モバイル端末でもアプリを快適に使用したい。そうすることで、外出先でも支払いを記録できる。

#### 受け入れ基準

1. WHEN ユーザーがモバイル端末でアクセス THEN システムはモバイル最適化されたレイアウトを表示する
2. WHEN ユーザーがデスクトップでアクセス THEN システムはデスクトップ最適化されたレイアウトを表示する
3. WHEN ユーザーが任意のページにアクセス THEN システムはヘッダーナビゲーションとパンくずリストを表示する
4. WHEN ユーザーが画面サイズを変更 THEN システムは適切にレイアウトを調整する

### 要件9：データセキュリティ

**ユーザーストーリー:** ユーザーとして、個人情報と財務データが安全に保護されることを期待する。そうすることで、安心してアプリを使用できる。

#### 受け入れ基準

1. WHEN ユーザーがパスワードを設定 THEN システムはパスワードをハッシュ化してデータベースに保存する
2. WHEN ユーザーがログイン THEN システムは認証トークンを使用してセッションを管理する
3. WHEN ユーザーが他のユーザーのデータにアクセスを試行 THEN システムはアクセスを拒否する
4. WHEN システムがデータベースに接続 THEN システムは環境変数から認証情報を取得する
