以下の仕様のアプリを作ってください。

## 概要

- 割り勘+家計簿アプリ
- 複数人での使用を想定

## ユースケース

- アプリにログインする
  - アプリにアクセスする
  - ユーザ名とパスワード（あらかじめDBに入っている）でログインする
  - トップページが表示される
- ユーザプロフィールを閲覧する
  - マイページにアクセスする
  - ログイン中のユーザのプロフィールが表示される
- ユーザグループを作成する
  - ユーザグループ作成ページにアクセスする
  - 必要事項を入力・選択してユーザグループを作成する
    - グループ名を入力
    - メンバーを招待
- 支払いを記録する
  - 支払い登録ページにアクセスする
  - カレンダーから日付を選択する
  - 必要事項を入力（一部はプリセットから選択）し、支払いを記録する
    - 会計のタイトル（例：東急ストア）を入力（プリセットあり）
    - 収入か支出かを選択
    - 会計のカテゴリ（例：食費）を入力（プリセットあり）
    - 誰がどれだけ支払うべきか（例：ユーザA・ユーザAとユーザBの割り勘・ユーザAが8割でユーザBが2割）を設定する
    - 実際に誰がどれだけ支払ったかを設定する
  - 「続けて入力する」ボタンを押すとスムーズに次の支払い記録に移れる
- 個別の支払い記録を閲覧する
  - 支払い詳細ページにアクセスする
  - 支払い記録と、精算済みか否かが表示される
    - 未精算の場合、その支払いに対して誰が誰にどれだけ支払わなければならないかが表示される
  - 「精算済みにする」ボタンを押すと精算済みになる
- 対象期間（全て/日毎/月毎/年毎）の支払い記録を閲覧する
  - 対象期間の支払い一覧ページにアクセスする
  - 未精算のみの表示（デフォルト）か、精算済みを含む表示かを選べる
  - 対象期間の未精算分に対して誰が誰にどれだけ支払わなければならないかが表示される
  - 未生産のみの表示の画面で「全て精算済みにする」ボタンを押すと、該当する分が全て精算済みになる
    - 「変更は戻せません。よろしいですか」のようなポップアップを表示する
- ダッシュボードを閲覧する
  - ダッシュボードページへアクセスする
  - グループ全体およびユーザごとに、以下に示すような情報が閲覧できる
    - 収入額・支出額
    - カテゴリごとの収支額と各カテゴリの割合
    - 今後の予測

## ページ

- トップページ（/）
- マイページ（/mypage）
- ユーザグループ関連ページ（/groups）
  - 一覧表示ページ（/）
  - 詳細表示（編集・削除込み）ページ（/[groupId]）
  - 作成ページ（/create）
- 支払い関連ページ（/groups/[groupId]/payments）
  - 一覧表示ページ（/）
  - 詳細表示（編集・削除込み）ページ（/[paymentId]）
  - 日毎の支払い一覧ページ（/[date(yyyy-mm-dd)]）
  - 月毎の支払い一覧ページ（/[month(yyyy-mm)]）
  - 年毎の支払い一覧ページ（/[year(yyyy)]）
  - 作成ページ（/create）
- カテゴリ関連ページ（/groups/[groupId]/categories）
  - 一覧表示ページ（/）
  - 詳細表示（編集・削除込み）ページ（/[categoryId]）
  - 作成ページ（/create）
- ダッシュボードページ（/groups/[groupId]/dashboard）

## 画面レイアウト

- レスポンシブデザインで作成し、モバイル端末で開いた際に表示が見やすいようにする
- ヘッダーを作成し、主要なページへのナビゲーションを用意する
- パンくずリストを作成する

## アーキテクチャ
- モノレポ
  - フロントエンド
    - ディレクトリ名：`frontend`
    - ポート：3000
  - バックエンド
    - ディレクトリ名：`backend`
    - ポート：4000
  - 共通部品
    - インターフェースなどの共通部品はは別の場所に配置してフロント・バック両方からアクセス可能にする
- データベース
  - Dockerで起動

## 技術セット
### 全体
- pnpm
### フロントエンド
- Nuxt.js
  - `pnpm create nuxt@latest frontend`で入れる
- NuxtUI
  - Nuxt.jsを入れた後、`pnpm add @nuxt/ui@alpha`で入れる
### バックエンド
- Nest.js
  - `nest new back --strict`で入れる
- TypeORM
- Docker
  - `backend`直下にdocker-compose.yamlを配置
- PostgreSQL
  - `image: postgres:latest`で作成
### 開発
- Biome
  - `pnpm add --save-dev --save-exact @biomejs/biome`で入れる
  - フロント・バックの両方で使うが、一部は独自の設定を使いたいので、それぞれのコンフィグファイルを作る

## その他
- 環境変数
  - .envファイルはフロント・バックそれぞれのルートに置く
  - ホスト名やパスワード系は.envに置く
- セキュリティ
  - ユーザのパスワードはハッシュ化してDBに保存
